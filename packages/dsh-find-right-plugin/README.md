# dsh-find-right-plugin

给 **DeepSeek Harness** 找到「**对的那个**」插件，而不是甩给 agent 一堆榜单。

本插件只给 agent 注册一个工具：`find_dsh_plugins`。它搜遍整个 DSH 插件生态，按 **相关度 × 可信度 × 新鲜度 × 热度** 四维排序，然后明确告诉 agent「最该装的是这一个」+ 为什么，只附少量高置信备选。

> 与 `dsh-find-plugin`（只按 star 排）以及市面上的 `dsh-find-plugins`（返回 top-N 榜单）不同：这里新增了**决策层**——目标是「找到对的那个」，不是「找一堆」。

---

## 它解决什么问题

用户说「想装个能跨会话记项目记忆的插件」时，agent 真正需要的不是 20 条结果，而是：

1. **一个明确的主推**：哪个最该装，凭什么（可核验的理由）。
2. **少量备选**：主推不合适时看哪 2–3 个即可。
3. **可信范围**：哪些数据源查了、哪些挂了，不能把「源挂了」伪装成「生态里没有」。

## 排序：四维乘积，不是只看 star

```
final = relevance × trust × freshness × popularity
```

| 维度 | 做法 | 为什么 |
| --- | --- | --- |
| 相关度 relevance | BM25 + 中文 bigram 分词 + 中英同义词扩展 + 名称加权；取 0.45 次幂压缩头部优势 | 「跨会话长期记忆」也能命中「跨会话记忆」；压缩后信任/热度才真正能左右结果 |
| 可信度 trust | 多源独立佐证 + 官方验证/实测加分；安全风险、归档、仅 topic 收录扣分 | 被多个目录共同收录、且经过验证的更可信；风险只做 tiebreak 不淘汰 |
| 新鲜度 freshness | 归档重罚；无日期给中立项；按更新年龄分段衰减；超 14 天再降权 | 三年没更的插件即使名字一模一样也不该赢 |
| 热度 popularity | `0.6 + 0.7 × log10(1+stars)/log10(5001)` 对数有界 | ★1 与 ★3000 只差约 1.5 倍而非 3000 倍，防止 ★70k 通用库碾压真插件；又不完全无视 star |

**这是乘积不是加权和**：任何一维接近 0 都会把整条拉下来。一个不相关但 ★70k 的通用库赢不了；一个名字一样但三年没更、只被 GitHub topic 收录的仓库也赢不了。

## 数据源（搜遍生态）

| 源 | 类型 | 说明 |
| --- | --- | --- |
| Awesome DSH 精选目录 (`dsh-plugin-catalog` via jsdelivr，含 fastly 镜像) | 主源 | 5126 条精选，中英双语描述 |
| dsh.works 目录 | 主源 | 32321 条，带 stars / 验证 / 推送时间 / tags |
| dsh.so / awesome-dsh-plugin / 蓝书 agent / dsh-plugin-radar | 补充 | 尽力而为；实测常 `ECONNRESET` 或连接超时，短超时快速失败 |
| GitHub 实时搜索 (`topic:dsh-plugin` / `dsh-plugins`) | 实时 | 按 query 现查，catch 新仓库 |
| npm 实时搜索 (`keywords:dsh-plugin`) | 实时 | 按 query 现查，catch 新发布的包 |

**单源失败绝不影响其它源，也不拖慢整体**：每个源独立硬超时、自带单源缓存与 stale-if-error；结果里逐源标注 `ok / 条数 / 错误 / 过期副本 / 截断`。主 CDN 挂了会自动切 fastly 镜像。

## 输出形态：一个插件一张卡片，一张接一张

**不用表格**——多列 + 长中文会把会话宽度撑爆、格子挤成一块块。改成「一个插件一张卡片，一张接一张」：
每张卡是竖向单列、宽度恒定、自包含，主推与全部备选各成一张卡，按推荐顺序排下来。
看每张卡开头的「它是做什么的（用途）」就能第一时间判断是不是所需，不用在别处来回对照。

每张卡片包含：用途 / ★star 与 30 天下载 / 优势 / 需留意 / **综合评分拆解**（四个数字各自标名字）/
为什么推荐它 / 安装目标 / **可点击的来源网址**（点开直接跳转）。卡片之间用分隔线隔开。

「来源网址」优先采用各数据源**真实记录**的网址（Awesome DSH 目录页 / dsh.works 目录页 /
GitHub 仓库 / npm 包页…），按域名如实标注，**不强求都是 GitHub**；只有在数据源没记录到网址时，
才用仓库名或包名兜底拼一条 GitHub / npm 链接。一行可放多条，点哪个跳哪个。

「★star / 30天下载」：★ 是 GitHub 星数；`30天 N↑/↓/→` 取自 npm downloads API 近 30 天下载量与趋势
（↑ 后半月日均比前半月高、↓ 更低、→ 持平，波动 <5% 算持平）；纯 GitHub 安装目标不在 npm 则显示 `30天 —`。
**该项只作人气参考，不参与排序**，与「热度」维度（对数有界乘子）是两回事。

## 综合评分怎么读（四个数字各代表什么）

**综合分 = 相关度 × 可信度 × 新鲜度 × 热度**（四维相乘，不是加权平均）。每张卡的「综合评分拆解」已经把四个数字各自标了名字。

- **相关度**：查询词与「名称 + 描述 + 分类 + 标签」的匹配程度。**相对值**：本轮最佳 = 1，其余按 0.45 次幂压缩。
- **可信度**：来路是否可靠、是否经过验证。**1 = 基线**；上限 2、下限 0.25。
- **新鲜度**：维护是否活跃。**1 = 近期活跃**；归档 0.4；无日期 0.85。
- **热度**：受欢迎程度（★star）。**0.6 ~ 1.3**，对数有界，防 ★70k 通用库碾压真插件。

> 两个常见误解：①「相关度 0.593」是**相对本轮最佳**的压缩值，不是绝对匹配率；②综合分高 ≠ 功能最全。挑插件先看卡片「用途」是否对症。

**设计要点**

- **不用表格**：卡片是竖向单列，宽度恒定，长中文不会撑爆会话或被挤成碎块；这是按用户连续反馈定下的版式。
- **评分不再天书**：每张卡的「综合评分拆解」用「相关度 X × 可信度 X × 新鲜度 X × 热度 X = 综合 X」把四个数字各自标名字；文末再逐条解释各维度衡量什么、基准与范围，并点破「相关度是相对本轮最佳的压缩值，不是绝对匹配率」。
- **备选也写清用途**：主推与备选共用「统一画像」（用途 / 四维分 / 可核验信号），由 `decide.js` 的 `profileOf` 产出，渲染层据此让每个插件都自包含成一张卡。
- 不硬凑：最佳条目若只命中了 `dsh` / `插件` 这类泛词（查询内容词覆盖率过低），会如实说「没找到足够匹配的」，而不是推一个凑数的包。判定用与语料规模无关的覆盖率 / 名称命中，避免 BM25 绝对分随语料大小漂移。
- 主推必能装：主推候选的 npm 目标若明确核验失败（不是插件 / 仓库不符），决策层会顺位换人并说明原因；全部候选都核验失败时不硬推。网络抖动导致「无法核验」不等于「不是插件」。
- 分差很小会标注「前几名很接近」，置信度相应下调。

## 工具参数 `find_dsh_plugins`

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `query` | string | 必填 | 想找什么插件，用功能词描述，中英文均可 |
| `limit` | number | 4 | 返回条目总数上限 1–8：主推 1 个 + 最多 3 个备选。调大只增加备选，不铺开榜单 |
| `includeUnvetted` | boolean | false | 是否放出「仅被 GitHub topic 收录、零 star」的未验证下限条目 |

## 安装

```bash
dsh plugin --profile <你的 profile> add <本插件目录或 tarball>
# 装完重启 DSH 生效
```

或把本目录作为本地 bundle 挂到 profile 的 `cordis.patch.yml`：

```yaml
- insert:
    - id: dsh-find-right-plugin
      name: 'dsh-find-right-plugin'
```

依赖（peer，宿主提供）：`@deepseek-ai/cordis ^4.0.2`、`@deepseek-ai/dsh-tools ^0.1.5-rc.2 || ^0.2.0-rc.1`。要求 Node ≥ 22、DSH `>=0.1.5-rc.2 <0.3.0-0`。

## 可选配置

| 环境变量 | 作用 |
| --- | --- |
| `GITHUB_TOKEN` / `SCOUT_GITHUB_TOKEN` / `DSH_FIND_RIGHT_PLUGIN_GITHUB_TOKEN` | 提升 GitHub 匿名 10 次/分限流到 30 次/分（可选，缺失不影响） |
| `DSH_FIND_RIGHT_PLUGIN_NO_PREWARM=1` | 关闭启动 5 秒后的后台目录预热 |
| `DSH_HOST_VERSION` | 覆盖宿主版本检测（测试用） |

## 设计边界（刻意）

- **只读**：绝不安装 / 启停 / 改 profile / 写 `cordis.patch.yml`；安装命令只作为文本建议给出。
- **不自带离线快照**：把陈旧数据冒充实时比没有更糟；缓存只在进程内、且过期会标注。
- **不自己调模型**：调用方 agent 就是模型，再花一次调用重排更慢更笨。
- **不感知桌面外壳**：任何 DSH 实例都能用。
- 第三方插件请自行阅读源码与权限后再安装。

| `decide.js` | **决策层**：主推 1 个 + 少量备选 + 可核验理由；`profileOf` 产出主推/备选统一画像供卡片 |
| `render.js` | 中文渲染（源状态 / 一个插件一张卡片 / 四维分带名字 / 评分逐项释义 / 来源网址按域名如实标注 / 安装建议；不用表格） |
